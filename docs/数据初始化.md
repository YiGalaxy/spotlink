# 数据初始化

宿主只需 Docker Desktop、Compose v2、Git 与 Windows PowerShell。Java、Node、MySQL 和生成器均在容器内运行。

## 一键入口

```powershell
# 首次构建、迁移、生成、导入、验证并启动
.\setup-demo.cmd -NoPause

# 日常启动：沿用配置、数据和同一导入流程
.\start.cmd -NoPause

# 已有镜像时，单独完成最小数据准备与导入
.\import-data.cmd -NoPause
.\data-status.cmd -NoPause
```

当前实现 `minimal`，默认批次 `minimal-v1-20261009`；`demo` 完整交易场景将在 C37 扩展，当前请求 `demo` 会失败，不把最小包冒称完整演示。`acceptance` 与 `performance` 的基础包也可生成，但应使用独立配置、项目和数据库，不与 minimal 混合。

导入器只通过后端 JAR 的部署 CLI 运行，没有 HTTP 导入接口，没有 SQL 或数据库工具向 AI 开放。CLI 只接收白名单命令和批次名，数据库配置来自容器环境，不在命令行拼接密码。只读挂载数据定义与生成包，不传入模型 Key。

## 分步执行

每一步都有同名 `.cmd` 和 `.ps1`。PowerShell 参数可指定 `-Dataset`、`-Batch`、`-ProjectName`、`-EnvFile`、`-NoPause`；生成默认沿用并验证已有兼容批次，`-Resume` 表达继续执行，不能覆盖或重置。

```powershell
.\scripts\data\check-environment.ps1
.\scripts\data\start-infra.ps1
.\scripts\data\migrate-schema.ps1
.\scripts\data\prepare-dataset.ps1 -Dataset minimal
.\scripts\data\import-business.ps1 -Dataset minimal
.\scripts\data\import-knowledge.ps1 -Dataset minimal
.\scripts\data\verify-dataset.ps1 -Dataset minimal -Scope runtime
```

迁移使用应用原有 Flyway 定义和锁。业务导入前由 Node 重新生成并比较规则、JSON、JSONL、SQL、expected 和 SHA-256 清单；Java 再校验文件、版本、白名单列、编号、依赖、单位和数量。审阅 SQL 不作为执行输入，实际值通过参数绑定写入。

迁移、导入和验证期间暂停当前项目原先运行的前后端，避免写入、定时扫描和通知竞争，结束后在 `finally` 恢复。数据库命名锁覆盖导入与验证，本机文件锁覆盖维护步骤；发生冲突时拒绝执行。

## 最小包

三个虚构企业、一个仓库、电解铜品类、三条库存、五个账号和平台角色关联。数据 ID 在独立命名空间内，业务编号以 `SL-MIN-` 开头。所有联系资料、地址和库存均为合成示例。

| 账号 | 身份 |
| --- | --- |
| `min_seller01` | 示例企业 1，两条库存 |
| `min_buyer01` | 示例企业 2，一条库存 |
| `min_empty01` | 示例企业 3，无库存 |
| `min_admin` | 平台管理员 |
| `min_auditor` | 平台审计员 |

本地演示口令为 `Admin@123`，由实际 BCryptPasswordEncoder 在服务器编码。重复导入不重写密码，也不把已经修改的库存恢复到初始值。原有 `admin`、`seller01` 等开发账号保持兼容。

中文原文在 `data/knowledge`，含采购比较、运费与资料边界、库存字段/单位和本地交易说明。确定性分块携带标题、来源、版本、原文行号；文档元数据保存原文/规范化散列、可见性、生效范围和切块配置。正文和关键词索引独立导入，不调用模型。没有 Embedding 时 `embedded=0` 明确表示未构建，不能宣称向量 RAG 就绪。

## 台账与恢复

业务记录、归属映射与阶段成功台账同事务提交。`t_dataset_import` 保存 dataset/version/sourceHash/recordsHash、批次、时间锚、行数和提交时间；`t_dataset_record` 保存表、稳定 ID、业务编号、场景与内容散列。相同数据版本及内容重复执行时，核验归属、兼容性和当前不变量后返回 `SKIPPED`。

同版本内容变化、已有其他包、ID 碰撞或人工记录占用了业务编号，均报告冲突，禁止 `INSERT IGNORE`、`REPLACE` 或自动清库。当前阶段失败回滚，成功前序阶段保留。客户端在提交过程中断开时显示结果待核验，先看数据库台账再重试，不把本地文件当作成功证据。

`-Scope initial` 比较刚导入的初始字段和库存，适用于隔离重建。`-Scope runtime` 核对归属、身份引用、单位及数量守恒，允许库存、状态、密码等经过正常用户操作变化。

| 退出码 | 含义 |
| --- | --- |
| 0 | 当前请求完成，或已成功且核验后跳过 |
| 1 | PowerShell 参数绑定失败（未知参数或无效 Scope） |
| 3 | Docker 等依赖缺失 |
| 4 | 不支持的数据包/命令、数据文件、规则、结构或校验失败 |
| 5 | 导入锁、版本、归属或业务编号冲突 |
| 6 | 数据库执行/连接失败，提交结果可能须查台账 |

结构迁移失败不能假称 DDL 回滚；按 Flyway 诊断和备份恢复处理。没有自动 repair、重置或清理用户数据。修改 `data` 定义会改变 sourceHash，已有生成批次不得覆盖；使用新批次，并按版本化升级或新的独立演示库部署。
