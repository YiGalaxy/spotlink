# SpotLink 项目导读与面试准备

这份文档以当前代码为准，帮助快速理解项目、准备演示和 Java 实习面试。它是学习路线，不应把未实现的生产能力说成已经上线。

## 项目一句话

SpotLink 是一个面向企业的大宗商品现货交易平台原型：企业完成审核后登记库存、发布挂牌，交易对手摘牌形成订单，双方签署合同，再按约定完成交收。平台不做期货式集中撮合；挂牌和摘牌的业务语义决定了订单状态、库存冻结与权限边界。

## 一笔交易怎么走

1. 用户登录，后端验证 JWT，并加载用户状态、企业范围和权限。
2. 企业录入电子库存单。卖方发布挂牌时，库存从可用量移入冻结量，货权仍归卖方。
3. 买方摘牌后生成订单。`AUTO` 挂牌可以直接成交；`MANUAL` 挂牌先等待挂牌方确认，等待期间预留数量但不转移货权。
4. 订单按状态机推进。接口根据当前用户返回可执行动作，服务端再次验证权限和状态；数量更新用版本字段处理并发竞争。
5. 订单生成合同快照，买卖双方签署后推进至已签约。交收进度继续记录在订单状态和状态日志里。
6. 结算模块模拟资金账户、冻结和流水；它不连接真实银行或第三方清算机构。
7. 成交事件更新行情；服务端通过 SSE 推送行情和待办变化。

## 代码地图

后端入口在 `backend/src/main/java/com/bulk/trade/BulkTradeApplication.java`，按业务模块组织，而非把所有 Controller、Service、Mapper 放在各自的大目录里。

| 模块 | 职责 | 建议先读 |
|---|---|---|
| `shared` | API 响应、异常、安全上下文、JWT、审计、SSE 通知 | `SecurityConfig`、`JwtAuthenticationFilter`、`GlobalExceptionHandler` |
| `identity` | 企业、用户、角色权限和认证 | `AuthServiceImpl`、`UserAuthorityServiceImpl` |
| `inventory` | 电子库存单与可用/冻结数量 | `InventoryService`、`InventoryViewAssembler` |
| `trading` | 挂牌、摘牌、订单状态机、待办和超时扫描 | `ListingService`、`OrderService`、`OrderProgress`、`TradingSweepJob` |
| `contract` | 合同快照与双方签署 | `ContractService` |
| `settlement` | 模拟账户、流水、冻结与解冻 | `FundService`、`FreezeService` |
| `marketdata` | 从成交记录聚合行情并通过 SSE 推送 | `MarketService`、`MarketBroadcaster` |
| `knowledge` | 规则文档分块、嵌入、混合检索 | `EmbeddingService`、`KnowledgeService` |
| `advisor` | Spring AI 工具调用、会话、合同审查与 RAG 工具 | `AdvisorAgent`、`KnowledgeAdvisorTools`、`SystemPromptBuilder` |
| `admin` | 企业审核、后台查询、权限管理和审计 | `AdminEnterpriseService`、`AdminController` |

前端入口在 `frontend/src/main.tsx`。`api/` 封装 HTTP，`pages/` 是页面，`router/` 管访问路由，`store/auth.ts` 保存认证状态，`hooks/useTaskStream.ts` 消费 SSE。前端负责呈现和交互；权限和业务规则仍由后端强制执行。

数据库结构由 `backend/src/main/resources/db/migration/V*.sql` 管理，启动时 Flyway 按版本迁移。Mapper 执行持久化和查询，Service 维护事务及业务不变量，Controller 负责 HTTP 输入输出。

## 技术栈怎么讲

| 技术 | 在这个项目中的用途 | 学习时重点 |
|---|---|---|
| Java 21 | 后端语言 | 集合、泛型、异常、日期时间、BigDecimal、并发基础 |
| Spring Boot 3.5 | 自动配置、依赖注入、Web 服务 | Bean 生命周期、配置绑定、切面、事务边界 |
| Spring MVC / Validation | REST API 和请求校验 | Controller DTO、参数校验、统一异常响应 |
| Spring Security + JWT | 身份认证和权限控制 | 认证过滤器、SecurityContext、权限码；JWT 本身不是授权逻辑 |
| MyBatis-Plus | Mapper、实体 CRUD、逻辑删除 | SQL 与 ORM 的边界、更新策略、乐观锁、事务 |
| MySQL 8 + Flyway | 业务数据和可重复的 schema 迁移 | 约束、索引、事务、一致性；迁移脚本不要在旧版本上改写 |
| Redis | 请求权限加载的缓存及相关基础设施 | 缓存键、过期和失效策略；它不是业务事实来源 |
| Spring AI 1.0 | Anthropic ChatClient 与 `@Tool` 工具调用 | 模型负责选择工具，Java 工具负责查询、权限和业务校验 |
| Ollama + BGE-M3 | 本地生成中文 embedding | 向量维度、余弦相似度、向量服务故障降级 |
| React 19 + TypeScript + Vite | Web 客户端 | 组件状态、类型化 API、路由和构建 |
| Docker Compose | 本地 MySQL、Redis 等服务 | 开发环境可复现，不等于生产部署方案 |

### AI/RAG 的实际数据流

用户问题进入 `AdvisorAgent`，Spring AI 让模型决定是否调用注册的 `@Tool`。工具方法通过注入的 Service 读取业务数据，工具调用切面记录轨迹。私有数据范围从安全上下文取得，工具不接受企业 ID 参数。规则问题调用知识检索工具：BGE-M3 向量召回与 MySQL ngram 全文召回各自产生排名，再由 `KnowledgeService` 用加权 RRF 合并，结果连同文档出处交给模型。

当前 MySQL 向量检索会把已嵌入分块读到 Java 内存精确计算余弦相似度，适用于当前小语料，不是大规模向量索引。embedding 服务不可用时检索仍可走关键词召回。AI 响应目前是普通 HTTP 完整返回，不是流式输出。

## 如何运行和验证

在仓库根目录启动 MySQL 和 Redis：

```powershell
docker compose up -d
```

后端需要 JDK 21 和 Maven：

```powershell
cd backend
mvn spring-boot:run
```

后端地址为 `http://localhost:8081`，接口文档为 `http://localhost:8081/swagger-ui.html`。演示数据脚本在 `scripts/`；先看 [README.md](../README.md) 的账号说明和执行步骤。

前端另开终端：

```powershell
cd frontend
npm install
npm run dev
```

前端默认地址为 `http://localhost:5173`。RAG 向量检索需要本地 Ollama 和 `bge-m3`；没有它时应用仍可启动并使用关键词降级。AI 对话还需要可用的 Anthropic 或兼容端点配置。

后端全量测试：

```powershell
cd backend
mvn test
```

纯单元测试可单独运行：

```powershell
mvn -Dtest=KnowledgeServiceTest test
```

部分集成测试使用 `local` profile 和 Docker Compose 的 MySQL/Redis；若测试失败，先区分代码断言失败与依赖服务未启动。前端构建检查：`cd frontend; npm run build`。

## 面试表达

### 30 秒版本

我做了一个 Java 21 和 Spring Boot 的大宗商品现货交易平台原型。业务主链路包括企业审核、库存登记、挂牌摘牌、订单状态流转、合同签署和模拟结算。后端按业务模块拆分，用 Spring Security 和 JWT 做认证授权，用 MyBatis-Plus 和 MySQL 持久化，Flyway 管理表结构。我重点实现了挂牌冻结、订单状态机和并发更新，也做了一个基于 Spring AI 工具调用及混合 RAG 的业务顾问，并用租户隔离测试验证私有数据范围。

### 3 分钟展开顺序

1. 先讲业务边界：现货平台是买卖双方协商成交，不是集中竞价；项目实现的是学习和演示原型。
2. 讲主流程：库存冻结、摘牌成单、订单状态推进、合同双方签署、模拟结算。
3. 挑一个后端难点：并发摘牌如何防超卖，说明事务、条件更新/版本校验和失败反馈。
4. 讲权限：JWT 识别用户，权限码决定操作，企业数据从登录上下文限定；AI 工具也不接受租户 ID。
5. 讲 AI：工具调用适合访问实时业务数据，RAG 适合回答规则文档；向量与全文分别召回，RRF 合并排名。
6. 主动讲取舍：结算是模拟；向量目前小规模全量扫描；SSE 是单向推送；模型结果非流式；规模化需要专门评估向量索引、分布式任务和生产密钥管理。

### 常见追问准备

| 问题 | 回答要点 |
|---|---|
| 为什么不用撮合引擎？ | 业务按双方就具体挂牌达成合同建模；撮合引擎和集中竞价不属于本项目的现货流程。 |
| 如何避免超卖？ | 数量冻结和状态检查在事务内完成，并发更新通过版本/条件更新检测竞争；失败时回滚并要求重试。可结合 `ListingService`、`FreezeService` 和交易测试说明实际路径。 |
| `AUTO` 和 `MANUAL` 有什么差别？ | 是否在摘牌时形成成交、谁拥有确认权、冻结和货权何时变化；`MANUAL` 等确认期间必须预留数量。 |
| 为什么用 `BigDecimal`？ | 金额和数量是十进制业务值，二进制浮点不能精确表示许多十进制小数。 |
| JWT 有了为什么还查权限？ | JWT 证明请求携带有效身份；当前权限和账号状态仍由服务端加载/校验，不能把令牌当永久权限快照。 |
| AI 怎么访问业务数据？ | 模型发起工具调用，工具是 Spring Bean，走现有 Service；模型不生成 SQL，也不拥有数据库凭据。 |
| 怎么防止 AI 跨租户？ | 工具没有企业 ID 入参，租户从认证上下文取得；针对列举和猜 ID 两类访问做隔离测试。 |
| RRF 有什么好处？ | 向量余弦相似度和全文相关度分数不可直接比较；RRF 使用排名融合，降低分数尺度校准问题。 |
| 当前 RAG 的瓶颈？ | MySQL 中的 BLOB 向量全量加载到 Java 打分；小语料简单准确，增长后应换有向量索引的存储并用检索集评估召回质量。 |
| 哪些还不是生产实现？ | 资金是模拟账户，不接第三方清算；向量检索只适合小规模；要按部署环境配置密钥和安全参数。 |

回答时尽量按“业务不变量 → 代码落点 → 测试证据 → 当前限制”组织，不要只背技术名词。
