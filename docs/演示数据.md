# 演示数据

`DevelopmentDataInitializer` 只建 3 家企业、4 个账号——**数据库基本是空的**。要看到
一个有内容的市场，跑 `scripts/` 下的脚本。

---

## 用法

```bash
cd scripts

run() {
  docker exec -i spotlink-mysql mysql --default-character-set=utf8mb4 \
    -ubulk -pbulk_trade_2026 bulk_trade < "$1"
}

run generate-demo-data.sql          # 历史成交，供行情曲线使用
run generate-inflight-orders.sql    # 覆盖全部订单状态的在途订单
run generate-rich-catalogue.sql     # 100 条基础品类随机组合出的数百条记录
run backfill-demo-contracts.sql     # 给历史订单补上它们本该有的合同
run topup-seller-inventory.sql      # 给 seller01 补一点能卖的货
```

**全部幂等**，跑几遍都不会重复。

---

## 两个必须知道的坑

### 一、`--default-character-set=utf8mb4` 不能省

容器里的 mysql 客户端**没有 locale，默认 latin1**。不加这个参数，脚本里的中文会被
**双重编码**写进库里——看起来是乱码，而且事后很难分辨哪些行是坏的。

PostgreSQL 当年是自己协商编码的；MySQL 客户端必须显式告诉它。

脚本内部也要有 `SET NAMES utf8mb4;`，因为管道输入时客户端读的是文件内容。

### 二、企业 ID 必须按 `enterprise_code` 解析，绝不能硬编码

雪花 ID 是时间相关的，**重建数据库就会换一批**。

踩过一次：`topup-seller-inventory.sql` 硬编码了企业 ID，在 PostgreSQL 那套库上能用，
迁到 MySQL 后 ID 全变了——四张库存单挂到了一家**不存在**的企业上。**没有报任何错**，
唯一的症状是「被告知有的货不见了」，而沉默和「本来就没有」是无法区分的。

脚本现在一律 `JOIN t_enterprise ON enterprise_code = ?`。

---

## 脚本之间为什么要按这个顺序

| 脚本 | 前提 |
|---|---|
| `generate-demo-data` | 无。它建演示企业和库存单 |
| `generate-inflight-orders` | 需要企业已存在（按 code 解析，缺失会 `SIGNAL` 报错） |
| `generate-rich-catalogue` | 无。它自建企业和库存单 |
| `backfill-demo-contracts` | 需要 `generate-demo-data` 已跑（它补的是那批历史订单） |
| `topup-seller-inventory` | 需要 `ENT20260920001` 存在（种子数据自带） |

## 演示数据里有什么

跑完之后大致是：

```
企业 9 · 库存单 500+（100+ 个品种）· 挂牌 200+ · 订单 300+
合同 200+（全部已签署）· 知识分块 77
```

订单覆盖全部六种状态，`seller01` 能看到几十笔待办。

## 价格是按品种算的，不是占位符

`generate-demo-data.sql` 里有一个比值表：电解铜 ×1.00、铝锭 ×0.36、锌锭 ×0.39、
碳酸锂 ×2.00。

**这不是装饰。** 早期版本给挂牌价写成 `68000 + 行号`，于是**铝锭被标成 68132 元/吨**
——真实价格的两倍多。不报错、不打日志，唯一的症状是一个**不懂铝价的人看着完全正常**
的数字。而且顾问已经开始绕着它推理：它把一条异常低的标成数据错误，却默默接受了
五条异常高的。

**这个 bug 是「问一个真人会问的问题」发现的**（「目前挂牌的最便宜的货物是啥」）。
