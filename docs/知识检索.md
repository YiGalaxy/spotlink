# AI 知识检索与向量索引

聊天模型负责理解问题和组织答案；向量模型负责把问题与平台原文转换成可比较的数值。两个模型独立配置，浏览器不接触凭证。

## 本地启用

```powershell
.\scripts\setup-knowledge-model.cmd
.\scripts\build-knowledge-index.cmd
```

第一个命令下载 Ollama 的 BGE-M3 并启用后端向量服务，保留聊天 API 配置。第二个命令提示输入有知识库管理权限的账号密码，逐批建立索引；令牌只保存在运行内存，状态文件写入被 Git 忽略的 `.local/knowledge`。

```powershell
.\scripts\build-knowledge-index.cmd -StatusOnly
```

云端兼容服务填写 `.env` 中的 `SPOTLINK_EMBEDDING_URL`、`SPOTLINK_EMBEDDING_MODEL`、`SPOTLINK_EMBEDDING_API_KEY` 与实际 `SPOTLINK_EMBEDDING_DIMENSIONS`。地址支持根路径或 `/v1`，请求由 Spring AI `EmbeddingModel` 发往 `/v1/embeddings`；聊天后台配置与它独立。

## 索引有效性与恢复

每个向量记录服务/模型/维度/版本指纹、原文 SHA-256 和建立时间。更换配置或修改原文后，旧向量不参与检索，重新运行索引命令只处理缺失或失效块。同名模型更换权重时增加 `SPOTLINK_EMBEDDING_REVISION`。停用、删除文档同时排除于关键词和向量检索。

索引逐块提交，模型 HTTP 请求不占数据库事务；中断前成功的块保持可用。写入再次检查原文散列，避免构建期间文档变更后写入旧向量。服务故障、超时、空值、非有限数值、全零或错误维度不会写入假向量；本批无进展会非零退出，修复后可重跑。

当前向量存放在 MySQL BLOB，服务按余弦相似度扫描最多 5,000 块，与 ngram FULLTEXT 的关键词候选按加权 RRF 融合。它适合本项目小型平台语料；达到扫描上限时需要扩展向量存储，而不能据此宣称覆盖更大的语料集。检索结果最多 8 块，顾问默认使用 4 块。

没有有效向量或向量服务不可用时，关键词仍可返回有原文依据的结果。索引状态中的 `embedded` 只统计当前指纹和原文有效的块，`pending` 包括旧模型或旧原文的向量。

## 验证

旧 `RULE-*` 与旧保证金、费用、快速入门示例已停用，避免把未实现的清算、统一保证金和异议期限当作平台承诺。新版 `APP-*` 描述当前实际功能，`GUIDE-PROCUREMENT` 与 `GUIDE-ACCEPTANCE` 是一般采购核对建议；不会凭空设定运费、税率或合同期限。生成批次源文件保持不变。

顾问回答附带服务端检索得到的原文卡片，点击显示文档编号、版本、段落和原文快照。引用与问答一起持久化，刷新会话仍可核对；原文按普通文本显示，模型不能自造引用编号。历史快照反映当时依据，不代表文档仍在生效。

`EmbeddingServiceTest` 验证真实 Spring AI HTTP 请求、中文编码、端点路径、维度和索引身份；`KnowledgeIndexIntegrationTest` 在真实 MySQL 中检查原文修改、模型变更、停用文档及构建冲突。HTTP 替身仅验证适配契约，实际语义质量须由本地 BGE-M3 与真实问题独立验证。
